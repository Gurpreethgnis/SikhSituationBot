# Cloud Setup Guide ☁️

This guide outlines the steps needed to securely inject your new remote PostgreSQL `DATABASE_URL` and other required environment variables into your production environments (Vercel and Railway).

## 🚆 Railway Production Environment

Railway will host both your PostgreSQL database (with `pgvector` enabled) and your Flask backend, while keeping them automatically linked.

### 1. Provision PostgreSQL
1. Go to your [Railway Dashboard](https://railway.app/dashboard).
2. Click **New Project** (or open your existing backend project).
3. Select **Provision PostgreSQL**. Railway will instantly create a robust Postgres instance.
4. *Important Note for `pgvector`:* Railway's default PostgreSQL template supports installing `pgvector`. You can install the extension by either connecting via PSQL or using an initial migration. Once provisioned, execute `CREATE EXTENSION IF NOT EXISTS vector;` in your DB query editor or a connected client.

### 2. Link Backend the Database
1. Deploy your Flask backend service to the same Railway project (from your GitHub repo).
2. Go to your backend service > **Variables** tab.
3. You do *not* need to manually inject the database URL. Railway automatically injects a `DATABASE_URL` environment variable for internal access. 
4. Ensure your server is correctly referencing `os.environ.get('DATABASE_URL')`. *(Note: SikhSituationBot's `app.py` has already been confirmed to be configured correctly.)*

---

## 🔼 Vercel Production Environment

Vercel hosts the Next.js/Vite frontend. It needs to know how to talk to your new Railway backend.

### 1. Configure the API Connection
1. Go to your [Vercel Dashboard](https://vercel.com/dashboard).
2. Open the frontend project > **Settings** > **Environment Variables**.
3. Add the following variable:
   - **Key:** `NEXT_PUBLIC_API_URL`
   - **Value:** *`https://your-railway-backend-url.up.railway.app`* (Replace with the actual public URL generated by Railway for your backend service).
4. Click **Save** and select the production environment (and preview environments if necessary).

### 2. Redeploy
For the new environment variables to be bundled into the frontend build, you must trigger a redeployment in Vercel.

---

> [!IMPORTANT]
> **API Keys:** Make sure you also inject any other required keys (like `GEMINI_API_KEY`) into the Railway backend's variable dashboard safely. Do NOT commit actual API keys to GitHub.
